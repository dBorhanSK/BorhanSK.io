# Borhan_SK — Cloud Messenger Control

داشبورد فارسی مدیریت نشست‌های Telegram Web و اتوماسیون پیام‌ها با Flask، Playwright و Supabase.

## تغییرات این نسخه

- بازطراحی کامل رابط با هویت بصری Borhan_SK، رنگ سرمه‌ای و آبی/فیروزه‌ای و لوگوی اختصاصی SVG.
- صفحه «سلف و اتوماسیون» برای ساخت، توقف، ادامه و حذف زمان‌بندی‌ها و ارسال آزمایشی.
- ورود مالک با `OWNER_USERNAME` و `DASHBOARD_PASSWORD`.
- ساخت حساب مستقل برای ادمین‌ها از پنل مالک؛ رمز ادمین به‌صورت هش‌شده ذخیره می‌شود.
- جداسازی دسترسی: ادمین فقط حساب‌ها، گفتگوها، زمان‌بندی‌ها و گزارش‌های متعلق به خودش را می‌بیند؛ مالک فهرست و وضعیت تمام حساب‌های ادمین‌ها را می‌بیند، اما محتوای زمان‌بندی‌های ادمین نیز تا پیش از فعال‌سازی رضایت همان حساب پنهان می‌ماند.
- مالک همیشه برچسب و وضعیت اتصال حساب ادمین را می‌بیند. برای خواندن پیام‌های اخیر، ارسال پیام، ساخت اتوماسیون یا راه‌اندازی مجدد/حذف نشست ادمین، صاحب همان حساب باید مجوز «اجازه بررسی به مالک» را صریحاً فعال کند؛ این مجوز در هر لحظه توسط ادمین قابل لغو است.
- QR و ورود مجدد هر حساب فقط در اختیار صاحب همان حساب است. تمام اقدامات مالک روی حساب ادمین در گزارش همان ادمین نیز ثبت می‌شود.
- با حذف ادمین، نشست‌ها، داده‌های حساب و زمان‌بندی‌های او هم پاک می‌شوند و نشست ورود فعال او در درخواست بعدی بی‌اعتبار می‌شود.
- نامی که در کارت حساب دیده می‌شود برچسبی است که صاحب حساب هنگام افزودن انتخاب می‌کند؛ در این نسخه شماره تلفن یا نام کاربری تلگرام به‌صورت خودکار استخراج نمی‌شود.
- چند نشست مجزای Telegram Web؛ هر نشست BrowserContext مستقل دارد و از Chromium مشترک استفاده می‌کند.
- رمزگذاری نشست‌های Telegram Web با Fernet قبل از ذخیره در Supabase.
- CSRF، محدودسازی تلاش ورود و عملیات سنگین Telegram، کوکی امن HttpOnly/SameSite/Secure، HSTS و هدرهای امنیتی.
- نشست کوتاه‌تر، بررسی زنده اعتبار حساب ادمین، خروج اجباری ادمین حذف‌شده و ثبت اقدامات حساس مالک.
- محدودسازی کلیک‌ها به دکمه‌های صفحه‌کلید پاسخ تلگرام و تأیید خالی‌شدن کادر پیام پس از ارسال.
- محدودیت قابل تنظیم برای تعداد زمان‌بندی‌های فعال و کل هر حساب، برای جلوگیری از رشد کنترل‌نشده پایگاه داده.
- بهبود بازیابی خودکار Chromium و ذخیره دوره‌ای نشست‌ها.

## محدودیت‌هایی که باید بدانی

1. **در حال حاضر فقط Telegram Web واقعاً فعال است.** کارت WhatsApp و Discord/Slack در داشبورد صرفاً اعلام‌کننده توسعه آینده‌اند؛ اتصال واقعی آن‌ها به API رسمی، کلیدها و مجوزهای جداگانه نیاز دارد. از ظاهر داشبورد برداشت نکن که همه پیام‌رسان‌ها آماده‌اند.
2. **این برنامه کلاینت Telegram Web را با Playwright کنترل می‌کند، نه MTProto/TDLib.** تغییرات رابط یا selectorهای تلگرام ممکن است نیاز به اصلاح کد داشته باشد. عملکرد ورود QR و ارسال زنده باید روی حساب آزمایشی بررسی شود.
3. **تعداد حساب‌ها نامحدود و بدون محدودیت منابع نیست.** هر حساب یک BrowserContext جدا باز می‌کند؛ حافظه و CPU پلن Render، به‌خصوص Free با 512MB RAM، محدودیت واقعی ایجاد می‌کند. افزودن تعداد زیاد حساب ممکن است باعث Restart یا کمبود حافظه شود.
4. **Render Free تضمین 24/7 نمی‌دهد.** سرویس رایگان پس از 15 دقیقه بدون ترافیک ورودی می‌تواند Sleep شود و با درخواست بعدی معمولاً حدود یک دقیقه برای بیدارشدن زمان می‌برد. سرویس Free ممکن است هر زمان Restart شود و Persistent Disk ندارد. KeepAlive برنامه فقط best-effort است و تضمین یا راه رسمی حذف محدودیت پلن نیست. وقتی سرویس خواب است، scheduler اجرا نمی‌شود.
5. نشست‌ها در Supabase به‌صورت رمزگذاری‌شده ذخیره می‌شوند؛ اما اگر `PROFILE_ENCRYPTION_KEY` را عوض یا گم کنی، نشست‌های قبلی قابل رمزگشایی نخواهند بود و باید QR را دوباره اسکن کنی. از این کلید یک نسخه امن نگهداری کن.
6. ستون `owner_access` به جدول `meow_accounts` اضافه شده است. برای مهاجرت، فایل کامل `supabase_schema.sql` را دوباره در SQL Editor اجرا کن؛ دستور `ADD COLUMN IF NOT EXISTS` داده‌های قبلی را پاک نمی‌کند و مجوز حساب‌های قدیمی به‌صورت پیش‌فرض خاموش می‌ماند.
6. برای اتوماسیون زمان‌بندی‌شده و نشست‌های مرورگر پایدار، یک سرویس همیشه‌فعال و دارای منابع کافی مناسب‌تر است. طبق محدودیت Render Free، دیسک پایدار برای این سرویس قابل افزودن نیست.
7. فقط حساب‌هایی را وصل کن که مالکشان هستی یا اجازه صریح صاحب حساب را داری. قوانین ضداسپم و شرایط استفاده پیام‌رسان‌ها را رعایت کن.
8. دسترسی مالک به محتوای حساب ادمین پیش‌فرض خاموش است. ادمین با فعال‌کردن این مجوز، اجازه خواندن پیام‌های اخیر و ارسال پیام/اتوماسیون توسط مالک را می‌دهد؛ برای QR و ورود مجدد همچنان باید خودش اقدام کند.

## راه‌اندازی / به‌روزرسانی

### 1) قبل از Deploy — Supabase

1. وارد Supabase → SQL Editor شو.
2. **کل فایل `supabase_schema.sql` جدید را اجرا کن.** اسکریپت برای جدول‌های قدیمی `ALTER TABLE ... IF NOT EXISTS` دارد و جداول اعضا و حساب‌ها را هم می‌سازد.
3. در Project Settings، آدرس پروژه و کلید Secret/Service Role سمت سرور را بردار.
4. هیچ‌کدام از کلیدهای Supabase را در HTML، JavaScript یا GitHub قرار نده.

### 2) GitHub و Render

1. فایل‌های داخل این نسخه را در ریشه repository قبلی جایگزین کن.
2. Render را از Blueprint به‌روزرسانی کن یا Environment Variables را مطابق زیر تنظیم کن.
3. متغیرهای ضروری:
   - `OWNER_USERNAME`: نام ورود مالک؛ پیش‌فرض `owner`
   - `DASHBOARD_PASSWORD`: رمز مالک، یکتا و طولانی (ترجیحاً 16 نویسه یا بیشتر)
   - `SECRET_KEY`: کلید تصادفی Flask
   - `WEBHOOK_TOKEN`: توکن تصادفی برای مسیر `/hooks/send`
   - `SUPABASE_URL`
   - `SUPABASE_SERVICE_ROLE_KEY`
   - `PROFILE_ENCRYPTION_KEY`: کلید Fernet؛ در طول عمر داده‌ها تغییرش نده
- `COOKIE_SECURE`: در Render روی `true` بماند؛ در اجرای محلی HTTP از `false` استفاده کن
4. برای تولید کلید Fernet:

```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

5. Deploy را انجام بده و `/health` را بررسی کن.

### 3) ورود و ساخت ادمین

1. آدرس سرویس را باز کن.
2. با `OWNER_USERNAME` و `DASHBOARD_PASSWORD` وارد شو.
3. در «مدیریت ادمین‌ها» برای هر ادمین نام کاربری و رمز اولیه بساز.
4. ادمین با همان نام کاربری/رمز وارد می‌شود و فقط اطلاعات خودش را می‌بیند.
5. در «حساب‌های متصل» برای هر Telegram Web یک برچسب مشخص انتخاب و نشست جدا بساز.
6. QR همان نشست را با Telegram گوشی اسکن کن: Settings → Devices → Link Desktop Device.

### 4) اتوماسیون

- در «سلف و اتوماسیون» حساب فرستنده را انتخاب کن.
- در «بررسی گفتگوها» نام کاربری یا مقصد را وارد کن تا پیام‌های اخیر همان گفتگو نمایش داده شوند.
- ابتدا ارسال آزمایشی را به مقصدی که در آن مجاز به پیام‌دادن هستی انجام بده.
- بعد زمان‌بندی ارسال یا کلیک را بساز. اگر مالک روی حساب ادمین اتوماسیون ساخته باشد، ادمین می‌تواند آن را در گزارش حساب خود ببیند؛ با لغو مجوز مالک، اتوماسیون‌های مالک برای آن حساب به‌طور خودکار متوقف می‌شوند.
- حداقل فاصله پیش‌فرض یک دقیقه است؛ حداکثر پیش‌فرض ۲۰ زمان‌بندی فعال و ۲۰۰ زمان‌بندی ذخیره‌شده برای هر حساب است (قابل تنظیم با `MAX_ACTIVE_JOBS_PER_ACCOUNT` و `MAX_TOTAL_JOBS_PER_ACCOUNT`). استفاده پرتکرار می‌تواند باعث محدودیت حساب شود.

## Webhook اختیاری ارسال فوری

این مسیر وبهوک Bot API تلگرام نیست؛ یک endpoint سرور-به-سرور است.

```bash
curl -X POST https://YOUR-SERVICE.onrender.com/hooks/send \
  -H "Content-Type: application/json" \
  -H "X-Webhook-Token: YOUR_WEBHOOK_TOKEN" \
  -d '{"account_id":"YOUR_ACCOUNT_UUID","target":"@your_group","text":"Hello"}'
```

`account_id` باید متعلق به مالک سایت باشد. توکن وبهوک را محرمانه نگه دار.

## اجرای محلی

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
playwright install chromium
Copy-Item .env.example .env
# مقادیر .env را تنظیم کن
python app.py
```

آدرس محلی: `http://127.0.0.1:10000` . اگر Supabase تنظیم نشود، SQLite محلی برای توسعه استفاده می‌شود.

## بررسی کد

```bash
python -m compileall -q .
PYTHONPATH=. pytest -q
```

تست‌های خودکار منطق ذخیره‌سازی را پوشش می‌دهند؛ صحت ورود QR، selectorهای Telegram Web و ارسال زنده بدون تست روی حساب واقعی قابل تأیید کامل نیست.
