# پچ نگهداری امن داده‌های Borhan_SK

این بسته فقط فایل‌های تغییرکرده را دارد؛ کل پروژه داخل آن نیست.

## چه چیزی اصلاح شده؟

- رویدادها و گزارش‌های قدیمی‌تر از `EVENT_RETENTION_DAYS` به‌صورت خودکار از جدول `meow_events` پاک می‌شوند. مقدار پیش‌فرض ۳۰ روز است.
- فایل‌های موقتی بارگذاری‌شده برای ارسال در تلگرام، بعد از `UPLOAD_RETENTION_HOURS` حذف می‌شوند. مقدار پیش‌فرض ۴۸ ساعت است.
- پاک‌سازی هر ۶ ساعت بررسی می‌شود و هنگام بیدارشدن مجدد سرویس نیز اجرا خواهد شد.
- حساب‌ها، مدیران، رمزهای هش‌شده، کارهای فعال و متوقف‌شده، اطلاعات حساب و پروفایل تلگرام به‌صورت خودکار حذف نمی‌شوند.
- خروج از پنل فقط نشست ورود وب را می‌بندد؛ عمداً اطلاعات و نشست تلگرام را حذف نمی‌کند.
- دو دستور مخرب انتهای فایل SQL حذف شده‌اند: دستور قبلی وضعیت تمام حساب‌های غیر Pending را به Pending برمی‌گرداند و دستور دیگر کلیدهای قدیمی runtime را پاک می‌کرد. نسخه جدید این داده‌ها را دست‌نخورده نگه می‌دارد.

## فایل‌هایی که باید جایگزین شوند

مسیرها نسبت به ریشه مخزن GitHub هستند:

- `backend/store.py`
- `backend/app.py`
- `backend/modules/desktop.py`
- `backend/tests/test_app.py`
- `supabase_schema.sql`
- `.env.example`

فایل‌های این بسته را دقیقاً در همان مسیرهای مخزن جایگزین کن. فایل‌های دیگر پروژه را تغییر نده.

## تنظیمات جدید

این سه متغیر را در Environment سرویس اضافه کن:

```env
EVENT_RETENTION_DAYS=30
UPLOAD_RETENTION_HOURS=48
CLEANUP_INTERVAL_SECONDS=21600
```

برای غیرفعال‌کردن حذف خودکار فایل‌های موقت، `UPLOAD_RETENTION_HOURS=0` بگذار. برای نگه‌داشتن رویدادها بدون محدودیت، `EVENT_RETENTION_DAYS=0` بگذار.

## درباره Supabase

اگر جداول فعلی قبلاً ساخته شده‌اند، برای فعال‌شدن پاک‌سازی دوره‌ای نیاز به اجرای مجدد SQL نیست؛ کد جدید از همان جدول `meow_events` استفاده می‌کند. اگر قرار است فایل `supabase_schema.sql` را دوباره اجرا کنی، نسخه همین بسته را جایگزین نسخه قبلی کن. قبل از هر اجرای SQL روی دیتابیس فعلی، از Supabase بکاپ بگیر.

## هشدار مهم درباره Koyeb Free

این پچ، پاک‌سازی ایمن داده را بهبود می‌دهد؛ اما به‌تنهایی پروژه را برای Koyeb Free به‌طور کامل سازگار نمی‌کند.

کد فعلی برای ورود تلگرام به Telegram Desktop واقعی متکی است و علاوه بر Flask، به Xvfb، Openbox، x11vnc، noVNC، OCR و چند پردازش سیستم‌عامل نیاز دارد. پروفایل ورود تلگرام در `/data/telegram/<account-id>` روی دیسک محلی نگهداری می‌شود. زمان‌بندی Self نیز در همان پردازش بک‌اند اجرا می‌شود.

پلن Free فعلی Koyeb فقط ۵۱۲ مگابایت RAM، ۰٫۱ vCPU و ۲ گیگابایت SSD موقت دارد؛ Volume پایدار و Worker برای این پلن ارائه نمی‌شود و سرویس پس از یک ساعت بی‌ترافیکی به صفر مقیاس می‌شود. بنابراین انتقال اطلاعات مدیریتی به Supabase، پروفایل Telegram Desktop و پردازش‌های درحال اجرا را حفظ نمی‌کند. اجرای این نسخه روی Koyeb Free می‌تواند به از دست‌رفتن نشست‌های تلگرام و توقف زمان‌بندی‌ها منجر شود.

**پس این بسته را به‌عنوان پچ پاک‌سازی امن استفاده کن، نه تأیید آماده‌بودن کل پروژه برای Koyeb Free.** برای حفظ تمام قابلیت‌های فعلی، باید یا میزبان دارای دیسک پایدار و منابع کافی انتخاب شود، یا موتور اتصال تلگرام از اساس به معماری دیگری بازنویسی شود.
