# Meow Studio Cloud Edition

نسخه ابری مدیریت اتوماسیون تلگرام با داشبورد فارسی، Flask، Playwright و Supabase.

## چه چیزی با نسخه قبلی فرق دارد؟

- کاربر در فرم تنظیمات، `API_ID` یا `API_HASH` وارد نمی‌کند.
- اتصال حساب از طریق QR داخل **Telegram Web رسمی** انجام می‌شود.
- Playwright مرورگر Telegram Web را روی Render باز نگه می‌دارد.
- پوشه پروفایل مرورگر باید روی Persistent Disk باشد تا نشست QR بعد از ری‌استارت از بین نرود.
- Flask داشبورد، API مدیریتی، مسیر سلامت `/health` و یک webhook سرور-به-سرور محافظت‌شده (`POST /hooks/send`) را ارائه می‌کند.
- HTTP KeepAlive به‌صورت پیش‌فرض هر ۴ دقیقه از طریق `RENDER_EXTERNAL_URL` به `/health` عمومی سرویس درخواست می‌فرستد؛ وضعیت آخرین تلاش، آخرین پاسخ و خطا در خروجی `/health` قابل مشاهده است. تنظیمات با `KEEPALIVE_ENABLED`، `KEEPALIVE_INTERVAL_SECONDS` و `KEEPALIVE_TIMEOUT_SECONDS` قابل تغییرند.
- Supabase کارها و رویدادها را نگهداری می‌کند.
- داشبورد از مرورگر ویندوز باز می‌شود؛ نصب نرم‌افزار جدا روی ویندوز لازم نیست.

> مهم: این پروژه اتوماسیون رابط کاربری وب است، نه اتصال مستقیم رسمی MTProto. Telegram Web ممکن است DOM یا رفتار ورودش را تغییر دهد و در آن صورت selectorهای Playwright باید به‌روزرسانی شوند. ورود با QR و اجرای زنده روی تلگرام در محیط ساخت این بسته آزمایش نشده است. هیچ‌کس نمی‌تواند بدون تست روی حساب واقعی تضمین «بدون باگ» بدهد.

## امکانات فعلی

- ورود QR به Telegram Web
- نگهداری نشست مرورگر روی دیسک پایدار Render
- ارسال پیام زمان‌بندی‌شده به گروه یا چت با نام یا `@username`
- کلیک زمان‌بندی‌شده روی دکمه اینلاین با متن مشخص
- ارسال آزمایشی از داشبورد
- خواندن متن چند پیام اخیر از چت انتخابی (بهترین تلاش با selectorهای UI)
- ساخت، توقف، ادامه و حذف زمان‌بندی‌ها
- اجرای محدود تا تعداد دلخواه
- گزارش رویدادها و خطاها
- داشبورد واکنش‌گرا و قابل استفاده در ویندوز/موبایل
- حداقل فاصله اجرا برای جلوگیری از ارسال‌های بسیار پرتکرار

## محدودیت‌های صادقانه

1. **بدون API_ID و API_HASH از طرف کاربر:** برنامه از وب‌اپ رسمی Telegram Web استفاده می‌کند؛ این وب‌اپ در زیرساخت خودش credential برنامه را دارد. ما credentialهای Telegram را استخراج یا جایگزین نمی‌کنیم.
2. **پایداری Render:** HTTP KeepAlive این پروژه هر ۴ دقیقه به `/health` از طریق `RENDER_EXTERNAL_URL` درخواست می‌فرستد تا ترافیک ورودی منظم ایجاد شود. این روش می‌تواند به فعال ماندن پلن Free کمک کند، اما Render چرخه عمر پلن رایگان را کنترل می‌کند و تضمین رسمیِ uptime دائمی نیست. Free پس از ۱۵ دقیقه بدون ترافیک ورودی می‌خوابد و دیسک پایدار ندارد؛ برای نشست پایدار Telegram Web از پلن پولی و Persistent Disk استفاده کن.
3. **Webhook:** وبهوک Bot API برای نشست Telegram Web کاربرد ندارد. Flask `/health` برای Render و API داشبورد است؛ پیام‌های Telegram Web از کانال ارتباطی خود مرورگر می‌آیند.
4. **تعامل با ربات‌های دیگر:** ارسال متن و کلیک روی دکمه‌های قابل مشاهده در UI پیاده شده، اما موفقیت امتیازدهی به منطق و قوانین ربات مقصد وابسته است. بعضی ربات‌ها تعامل اکانت‌های خودکار یا پیام‌های خاص را نمی‌پذیرند.
5. **Selectorها:** چون Telegram Web یک رابط وب پویاست، عملکرد Playwright در برابر تغییرات وب‌اپ تضمین دائمی ندارد.
6. **یک سرویس/یک پروفایل:** فقط یک نمونه Render با همین پروفایل را اجرا کن. دیسک Render همزمان به چند نمونه متصل نمی‌شود.
7. **Supabase Free:** پروژه رایگان ممکن است پس از یک هفته فعالیت بسیار کم pause شود. برای سرویس مورد اتکا، Pro را بررسی کن.
8. **امنیت:** ورود QR عملاً نشست حساب را روی سرور ذخیره می‌کند. رمز داشبورد را قوی انتخاب کن، از endpointها و QR اسکرین‌شات محافظت کن، و هیچ‌وقت `SUPABASE_SERVICE_ROLE_KEY` یا پوشه پروفایل را در GitHub قرار نده.

## راه‌اندازی روی Render

### 1) Supabase

1. در Supabase یک پروژه بساز.
2. از SQL Editor تمام فایل `supabase_schema.sql` را اجرا کن.
3. از Project Settings مقدار Project URL و کلید Secret سمت سرور را بردار.
4. فقط `SUPABASE_URL` و `SUPABASE_SERVICE_ROLE_KEY` را به Environment Render بده. کلید Secret را در کد، HTML یا GitHub قرار نده.

### 2) GitHub

1. این پوشه را در ریشه یک مخزن GitHub قرار بده.
2. مطمئن شو `Dockerfile` و `render.yaml` در ریشه مخزن هستند.
3. هیچ `.env` یا فایل نشست مرورگر را commit نکن.

### 3) Render

1. در Render گزینه **New → Blueprint** را انتخاب کن.
2. مخزن GitHub را وصل کن.
3. تنظیمات `render.yaml` را بررسی کن.
4. سرویس روی plan `standard` (معادل 1 CPU و 2 GB RAM در نام‌گذاری قدیمی) و دیسک ۲ گیگابایتی ساخته می‌شود. اگر قصد صرفاً آزمایش داری، می‌توانی دستی Free را انتخاب کنی، اما نشست/پایداری دائمی نخواهد داشت.
5. در Environment مقدارهای زیر را وارد کن:
   - `DASHBOARD_PASSWORD`: یک رمز طولانی و تصادفی برای ورود به پنل
   - `SUPABASE_URL`: آدرس پروژه
   - `SUPABASE_SERVICE_ROLE_KEY`: کلید Secret سمت سرور
6. Deploy را انجام بده و منتظر وضعیت Live بمان.

### 4) ورود به پنل و QR

1. آدرس `https://نام-سرویس.onrender.com` را در کامپیوتر باز کن.
2. با `DASHBOARD_PASSWORD` وارد شو.
3. به صفحه «اتصال تلگرام» برو.
4. QR صفحه Telegram Web را با گوشی اسکن کن: Telegram → Settings → Devices → Link Desktop Device.
5. پس از تأیید گوشی، داشبورد باید اتصال را سبز نشان دهد.
6. اگر QR به‌روز نبود، «تازه‌سازی QR» یا «بازکردن دوباره Telegram Web» را بزن.

### 5) ساخت کار

- در «زمان‌بندی‌ها» نام کار را وارد کن.
- مقصد را به‌صورت `@username` یا نام چتی که در حساب قابل جستجو است وارد کن.
- برای پیام تکراری، نوع «ارسال پیام» را انتخاب کن و متن را بنویس.
- برای کلیک روی دکمه، نوع «کلیک روی دکمه» را انتخاب و متن دکمه را دقیق وارد کن.
- فاصله را حداقل ۱ دقیقه تعیین کن؛ برای بازی‌ها فاصله ۵ دقیقه یا بیشتر منطقی‌تر است.
- تعداد اجرا اختیاری است؛ خالی یعنی تا وقتی خودت متوقف کنی.
- قبل از فعال‌کردن اتوماسیون، از «ارسال آزمایشی» مقصد را تست کن.

## Webhook اختیاری برای ارسال فوری

این webhook برای اتصال ابزارهای بیرونی به پنل است؛ **وبهوک تلگرام نیست**. درخواست نمونه:

```bash
curl -X POST https://YOUR-SERVICE.onrender.com/hooks/send \
  -H "Content-Type: application/json" \
  -H "X-Webhook-Token: YOUR_WEBHOOK_TOKEN" \
  -d '{"target":"@your_group","text":"میو"}'
```

مقدار `WEBHOOK_TOKEN` فقط در Render Environment نگهداری شود.

## اجرای محلی برای توسعه

روی ویندوز Docker Desktop یا Python 3.12 لازم است. برای اجرای بدون Docker:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
playwright install chromium
Copy-Item .env.example .env
# مقادیر .env را تکمیل کن
python app.py
```

سپس `http://127.0.0.1:10000` را باز کن. در حالت محلی، اگر Supabase تنظیم نشود، SQLite داخل `DATA_DIR` برای تست استفاده می‌شود.
